# AGENTS.md: DbGate Cloudron package working contract

The settled-decisions record for packaging **DbGate** (`dbgate`, GPL-3.0 community edition)
as a Cloudron community app. Read this before changing anything. Do not relitigate these
decisions without a concrete reason found on a running box. **The box is the authority, not
the docs.**

## What this package is

DbGate community edition, the web deployment of the open-source SQL/NoSQL client, packaged
unmodified from the upstream Docker image. No premium code, no licence keys, no storage
database.

Topology, all logging to stdout:

| Process | Role | Port |
|---|---|---|
| node (upstream bundle, `--listen-api`) | UI + RPC API + SSE + MCP | 3000 (the manifest `httpPort`) |
| forked children (per connection/session/job) | database drivers, isolation | none (IPC) |

State: no database addon and no bundled store. The DbGate workspace lives under
`/app/data/workspace` (`WORKSPACE_DIR`). Addons: `localstorage`, `oidc` only.

## Golden rules

1. **Conformance to the Cloudron contract first.** Adapt the runtime environment only; never
   patch the application.
2. **Pin everything by digest**: base image and upstream image. One build argument for the
   upstream version, mirrored as `upstreamVersion`.
3. **Persisted state only in `/app/data`.** Re-assert ownership and mode on every boot.
4. **Fail loud.** Never regenerate the workspace `.key` or the seeded admin credential; never
   clobber operator configuration in `/app/data/env`.
5. **Code and docs ship together.** ADRs in `docs/decisions/`; the verified-versus-assumed
   log in `docs/PACKAGING-NOTES.md`.
6. **`CMD`, never `ENTRYPOINT`.** Maintain `.dockerignore` (whitelist form) as carefully as
   `.gitignore`.
7. **Open core only.** Community image only; `STORAGE_*`, `DBGATE_LICENSE` and `ROLE_*` are
   never set. Premium-gated code paths in the community image are inert stubs and stay that
   way.
8. **Security floor.** `SKIP_ALL_AUTH`, `SHELL_CONNECTION` and `SHELL_SCRIPTING` are refused
   at boot. The workspace `.key` is 0600 inside a 0700 directory, re-asserted every boot.
9. **Anonymise before every push.** `test/secret-scan.sh` is the release gate; `example.com`
   is the placeholder in public docs.
10. **Git hygiene.** No AI co-authorship or tool-attribution trailers. Maintainer identity is
    set repo-local.

## Locked decisions (phase 0, operator-approved 2026-08-02)

- **Manifest id** `io.github.orcvole.dbgate`; image `ghcr.io/orcvole/dbgate-cloudron`,
  tags `<upstream>-<pkg-rev>`.
- **Auth topology**: app-native OAuth mapped from the `oidc` addon (`OAUTH_AUTH`/`OAUTH_TOKEN`
  from `CLOUDRON_OIDC_AUTH_ENDPOINT`/`CLOUDRON_OIDC_TOKEN_ENDPOINT`), `optionalSso: true`,
  no-SSO installs seed a generated `admin` login (operator-readable copy written before the
  credential takes effect). `loginRedirectUri` is `/` because the SPA sends
  `location.origin + location.pathname` as its OAuth redirect URI. No `proxyAuth`.
- **Layout**: the upstream tree is preserved verbatim at `/home/dbgate-docker` because
  `platformInfo` detects Docker mode by `fs.existsSync('/home/dbgate-docker/public')` and the
  bundled plugins path is hardcoded to `/home/dbgate-docker/plugins`. `/app/code` carries
  only `start.sh`. See `docs/decisions/0002-build-shape.md`.
- **Health**: `/health`, upstream's unauthenticated status endpoint, on the primary port.
- **memoryLimit**: 1.5 GiB initial; the gate ladder's memory gate settles the shipped value.
  Memory scales with concurrent connections (forked children), so the gate loads several.

## Secrets

| Secret | Shape | Criticality | Notes |
|---|---|---|---|
| `<workspace>/.key` | app-generated 32-byte key file | data-loss-critical (orphans stored connection passwords) | generated by the app on first run; never touched by the package except ownership/mode re-assertion; byte-identical across update and restore is a standing gate invariant |
| `/app/data/.secrets/admin-credentials` | generated login/password (no-SSO installs only) | seed-once | written 0600 BEFORE the credential takes effect; never reseeded |

Upstream wraps `.key` with a public hard-coded passphrase unless a CLI flag overrides it; the
package keeps the upstream default and treats the FILE as the secret (see ADR 0003 when
written). Never record secret values; the sha256 is the invariant.

| `OAUTH_SCOPE` | `openid profile email` | |

| operator extras | sourced from `/app/data/env` | `LOGIN_PASSWORD_*`, `LOGIN_PERMISSIONS_<login>` (applies to OAuth logins too, keyed by the `OAUTH_LOGIN_FIELD` claim; verified from source, `authProvider.js`), `PERMISSIONS`, `MCP_TOKEN`, `CONNECTIONS`, `OAUTH_ALLOWED_LOGINS`, `OAUTH_ALLOWED_GROUPS`, ... |

## Backup and restore

Everything rides the plain `/app/data` file backup: JSONL and small files at rest, no
churning store, no `persistentDirs`, no `backupCommand`. The update and restore gates prove
the `.key` byte-identical and saved connections intact.

## Future compatibility

The single bump point is the upstream version build argument plus the image digest.
Checked 2026-08-02: the 7.2.4 beta changes nothing packaging-relevant (auth, layout and
Docker context untouched; its env additions are premium-only role provisioning). Re-run the
tree-diff check against packaging-sensitive paths at every bump.
